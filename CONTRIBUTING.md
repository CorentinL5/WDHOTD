# Contributing to WDHOTD

Please contribute through [CorentinL5/WDHOTD](https://github.com/CorentinL5/WDHOTD). Read [DEV_WITH_US.md](DEV_WITH_US.md) for setup and the [project license](LICENSE) before copying or modifying code.

## What is welcome

Bug fixes, accessibility improvements, better historical context, image selection, timeline interactions, translations of documentation and small maintainability improvements. Open an issue before proposing a major redesign, new service dependency or data model.

Keep the product English, free to read, usable without an account, and inexpensive to host. Public requests must not write to MySQL or trigger Wikipedia imports. Never add tracking, payment processing or email collection without discussing it with the maintainer.

## Pull requests

1. Create a branch in a GitHub contribution fork or in this repository if you have access. Contribution forks are for proposing changes upstream, not for running an independent product.
2. Keep a pull request focused. Explain the user-visible problem and the resulting behavior.
3. Run the relevant checks in [DEV_WITH_US.md](DEV_WITH_US.md). Include screenshots for visual changes and describe keyboard/mobile checks.
4. Keep credentials, generated archives, database dumps with personal data, editor files and test logs out of commits.
5. Sign off commits with `git commit -s` and complete the pull request checklist. You must have the right to contribute the code and any media.

The owner reviews and merges changes. Passing CI does not automatically merge a pull request. Review comments must be resolved. Avoid force-pushing shared branches; rebasing your own contribution branch is fine.

## Security reports

Use the private reporting instructions in [SECURITY.md](SECURITY.md). Do not publish exploitation details or credentials in an issue.
